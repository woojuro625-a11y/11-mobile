# 인스타그램 훈련 피드 양식

러닝 훈련 기록 한 건을 음악 비트에 맞춰 소개하는 인스타그램 피드 영상 + 커버 이미지 양식.
기준 작업물: 2026.11.04 "2km×5+1km 롱 인터벌" (목동교 멀티스포츠존), 곡 Riverside Stride(123BPM, 54초).
`template/`은 그 영상을 만든 코드 그대로이며, 새 훈련에 맞게 **데이터·문구·비트 인덱스만 바꿔서** 쓴다.

## 산출물 규격 (고정)

| 항목 | 값 |
|---|---|
| 영상 | 1080×1350 (4:5 피드), **60fps**, H.264 + AAC, 길이 = 곡 길이 |
| 커버 | `out/cover.png` 1080×1350. **영상의 첫 0.1초(6프레임) = 커버 그대로** |
| 피드 카드 | `out/cards/card-02~08-*.png` 1080×1350 7장 — 영상(1번 슬라이드) 뒤에 이어 올리는 캐러셀. 마지막 카드는 **"우주로 달리기" 브랜드 카드**(로고 + 큰 문구) |
| 엔딩 | 곡의 마지막 강한 히트에 맞춰 커버로 복귀 → 피드 반복 재생 시 루프가 이어짐 |
| 음악 볼륨 | 원곡의 **80%** (`finish.sh`의 `volume=0.8`), 끝 0.25초 페이드 |
| 모션블러 | 프레임당 2샘플(180° 셔터), 후처리로 약한 블룸 + 그레인 |

## 표기 · 문구 규칙 (사용자 확정 사항)

- **페이스는 `3'54"` 형식** (분'초"). `/km` 단위 붙이지 않음. `fmtPace()` 사용.
- **제목은 `2KM`**(Anton 대문자), **설명 문구는 m 단위**: "2000m × 5 + 마지막 스텝", "2000m 동안의 심박 변화".
- **훈련 시작 시각은 넣지 않는다.** 날짜·요일만.
- **장소를 표기**한다 (핀 아이콘 + 장소명). 장소는 사용자에게 받는다 — GPS로 추정해 지명을 쓰지 말 것.
- **평균 러닝 파워는 넣지 않는다.**
- 사용자 실명, 절대 GPS 좌표는 넣지 않는다 (FIT 프로필에 이름이 있어도). `run-data.json`의 route는 상대 미터 좌표만.
- **화면·카드·캡션 문구에 쉼표(,)와 마침표(.)를 쓰지 않는다.** 구분이 필요하면 ` · `를 쓴다(숫자의 소수점은 예외).
- 모든 화면 문구는 한국어. 숫자·단위(km, m, bpm, spm, ms, kcal, Z1~Z5)만 예외.
- 마지막 장면은 감성 문구가 아니라 **"이 훈련은" 요약**: 01 목적 / 02 방식 / 03 결과.
- 회복 구간은 **평균 거리(m)** · 평균 페이스 · 평균 심박을 평균값으로 표시한다.
- **심박 그래프가 끊긴 곳(시계 일시정지)은 급수·완전 휴식**이다. 물방울 마커와 길이(초)를 표시하고 "그래프가 끊긴 곳 = 급수·완전 휴식" 범례를 단다. `PAUSES`는 기록 간격이 8초 이상 벌어진 곳(`extract_fit.py`가 `pauses`로 출력).
- 큰 숫자 잔상·배경 글로우에 라임을 진하게 쓰지 않는다(눈이 아프다는 피드백). 잔상은 회색 `#6B7480` 저투명도.

## 디자인 시스템

- 색: 배경 `#0B0D10`, 포인트 라임 `#D4FF3A`, 흰색 `#F3F2EC`, 심박 코랄 `#FF5A5F`, 회복 스카이 `#5CC8FF`, 회복 장면 배경 `#081521`.
- 심박존 색(가민 관례): Z1 `#7C8A9C` 회색 · Z2 `#5CC8FF` 파랑 · Z3 `#3DDC84` 초록 · Z4 `#FFB020` 주황 · Z5 `#FF5A5F` 빨강.
- 폰트: 한글 **Pretendard**(700~900), 큰 숫자·제목 **Anton**, 작은 라벨 **JetBrains Mono**.
- 모티프: 원근감 있는 트랙 오벌 + 라임 러너 점과 잔상, 속도선, 마스크 슬라이드 업 텍스트, 슬롯머신 숫자 롤, 비트마다 미세 줌 펀치(±1.2%)와 글로우 펄스.
- 상단 고정 HUD: 왼쪽 **훈련 이름 배지**(`2KM ×5 +1KM 롱 인터벌`), 오른쪽 진행 거리. 하단: 장면 구간 진행 바 + 현재 장면 이름.
- 여백 72px, 장면 왼쪽 위 `— 0N 섹션명` 라벨.

## 장면 구성 (곡 구조에 맞춘 비트 동기화)

비트 인덱스 `b(i)` = `beats.json`의 i번째 비트 시각. 아래는 기준 곡의 배치이며, 새 곡은 `analyze_music.py`가 출력한 마디/에너지 표를 보고 같은 **역할**을 같은 **음악 구간**에 배치한다.

| 기준 비트 | 장면 | 내용 · 규칙 |
|---|---|---|
| t < 0.1s | 커버 | `drawCover()` 정지 화면 |
| 0.1s ~ b8 (훈련 소개, 약 5.4초) | **훈련 이름을 길게** | 날짜 타이핑 + 장소 핀 → b0 "오늘의 훈련" → b1~b4 `2KM` `×5` `+1KM` `롱 인터벌 빌드업` 비트마다 슬램 → b5 "2000m × 5 · 세트마다 페이스를 끌어올린다" → b6 가속 화살표 → 제목을 b8까지 유지(미세 줌 드리프트). 아래에 트랙이 그려지고 러너 출발 |
| b8 ~ b16 (2마디) | **요약 카드 한 장** | b8에서 제목이 작아지며 왼쪽 위 배지로 이동(이후 엔딩까지 유지). 카드: 장소·날짜·기온 / 세션 전체(거리·시간·평균페이스·평균심박, 작게) / **본훈련**(거리·시간·평균페이스·평균심박, 크게) / 본훈련 심박존 막대 + "Z4 역치 구간에서 mm:ss (n%)". 짧게 가져간다 |
| b16 ~ b56 (첫 에너지 상승부터) | **본훈련 세트 × N (최대한 길게)** | 상승 지점에서 라임 플래시. **세트당 8박**. 세트 번호 + 우측 큰 **`2000m`** / 페이스 슬롯 롤 / **0→2000m 거리 진행 바(500m 눈금) → "2000m 완주"** / 목표 범위 게이지 + 적중 체크 / 평균·최대 심박 / 세트 심박존 막대 / "2000m 동안의 심박 변화" 그래프 / 하단 세트 페이스 칩 |
| b56 ~ b64 | 라스트 스퍼트 | "라스트 / 스퍼트" 오른쪽 빈 공간에 **"마지막 바퀴 약 520m"를 크게**. 마지막 스텝 페이스 큰 숫자 + 잔상, 목표 대비 몇 초 빠른지, 목표 범위·평균 심박 필 → 브레이크 직전 줌 인 |
| 브레이크 b64 ~ b72 | 회복구간 | 파란 톤. 제목은 **"회복구간" 한 단어**, 제목 오른쪽 빈 공간에 회복 목표(워크아웃 회복 목표 범위) 유지 체크 · 총 거리 · 총 시간 · 급수·휴식 횟수와 합계 시간. **정보를 처음에 한 번에 모두 표시**하고(제목, 회복 조깅 N회 평균: 평균 거리(m)·평균 페이스·평균 심박, 구간별 회복 페이스 칩), 이후에는 **비트마다 칩 하나씩 하이라이트 + 숫자 미세 펄스**로 대기 |
| 재상승 b72 ~ b96 | 분석 | ① 세션 전체 심박 그래프(1마디, 급수·휴식 마커 포함) ② 본훈련 심박존 도넛 + 존별 시간(1마디) ③ **세트별 존 100% 누적 막대(2마디)** — 두 번째 마디에 세트를 하나씩 테두리로 짚으며 존 구성(%) 표시 ④ **N/N 목표 페이스 적중** ⑤ 러닝 다이내믹스 + 훈련 효과 한 줄. **세트 후 심박 회복 장면은 넣지 않는다** |
| 드롭아웃 b96 ~ 마지막 히트 | "이 훈련은" 요약 | "이 훈련은" 다음 **훈련 유형(예: "빌드업 롱 인터벌")을 라임 박스 큰 문구로 강조** + 한 줄 설명(첫→마지막 세트 페이스), 이어서 01 목적 · 02 방식 · 03 결과가 2박 간격으로 등장 |
| 마지막 히트(b105) ~ 끝 | 엔드 카드 | 라임 플래시 후 커버로 복귀 |

곡이 다르면: 첫 에너지 상승(▲)에 세트 시작을, 브레이크(▼ 하강)에 회복 조깅을, 마지막 큰 에너지 구간에 분석을 둔다. 우선순위(사용자 피드백): **본훈련 세트 화면을 최대한 길게(세트당 8박 이상)** > 시작부 훈련 이름 노출 > 요약은 카드 한 장으로 짧게. 시간이 모자라면 요약·분석을 줄이고 세트 화면은 줄이지 않는다.

## 피드 카드 (cards.js, 영상 다음 슬라이드)

공통 틀: 상단 훈련 이름 배지 + `n / 8` 페이지, 큰 제목 + 부제, 하단에 장소·날짜와 한 줄 로고 "우주로 달리기"(흰색, 같은 서체).

| 파일 | 내용 |
|---|---|
| 02 세션 요약 | 총 거리·운동 시간·평균 페이스·평균/최대 심박·칼로리 + 본훈련 패널(거리·시간·평균 페이스·평균 심박) |
| 03 세트별 기록 | 위: **가민 워크아웃 구성**(`drawWorkoutPlan()` — 헤더 오른쪽 라임 필 "목표 범위 세트마다 -5초", 질주 블록 사이마다 점선 곡선 화살표 + "-N초" 배지로 빌드업 강조; **목표는 범위이므로 하한·상한을 같은 밝기로 한 줄 `4'00"~4'10"`에 묶고 블록 폭 괄호선을 붙인다**(하한만 강조하면 그 값이 목표처럼 보임); — FIT의 workout/workout_step: 워크아웃 이름, 질주 2km·1km 블록 + 목표 페이스 범위, 회복 "랩 버튼까지" 블록 + 회복 목표). 아래: 표 세트 · 거리 · 페이스 · 목표 범위(✓) · 심박 평균/최대 · Z4+Z5 %, 마지막 줄에 단축 요약. 워크아웃 구성은 `out/workout-plan.png`(1080×330)로도 따로 저장 |
| 04 심박 변화 | 세션 전체 심박 그래프(존 밴드·세트 음영) + **급수·휴식 마커**(물방울 + 초) + 범례 + 세트별 최대 심박 칩 |
| 05 심박존 분석 | 본훈련 존 도넛 + 존별 시간·% + 세트별 존 누적 막대 |
| 06 회복 & 라스트 | 회복 조깅 N회 평균(거리·페이스·심박) + 구간 칩 / 라스트 스퍼트 페이스 + 약 520m + 목표 대비 |
| 07 러닝 다이내믹스 | 케이던스·보폭·지면 접촉·수직 진폭·수직 비율·최고 속도 + 훈련 효과 게이지 |
| 08 우주로 달리기 (홍보) | 최소한으로. 정가운데 `woojuroText()` 로고 — **흰색 한 색, 장식 없음**(기울임·그림자·그라데이션·라임 강조 모두 금지, 사용자 피드백). 서체만 `window.BRAND_SIMPLE_FONT`로 바꿔 쓴다(기본 **Hahmlet ExtraBold**, 사용자 선택 6번). 후보 비교는 `template/font-options.html`(Orbit, Do Hyeon, Gasoek One, Song Myung, Gothic A1, Hahmlet, Jua, Bagel Fat One). 아래에 유튜브 아이콘 + "유튜브 채널", 인스타그램 프로필 줄(그라데이션 링 아바타 + "우주로 달리기" + 파란 `#0095F6` "팔로우" + 탭 표시). 그 밖의 문구 없음 |

파워·심박 회복은 카드에도 넣지 않는다. `node render.mjs --cards`로 `out/cards/`에 저장.

## 작업 순서

1. **환경 준비**
   ```bash
   python3 -m venv <scratch>/venv && <scratch>/venv/bin/pip install fitparse numpy librosa soundfile
   ```
   새 작업 폴더를 만들고 `template/`의 파일을 복사한 뒤 `npm i` (pretendard, @fontsource/anton). Chromium/Playwright는 환경에 설치된 것을 쓴다.
2. **데이터 추출**: `python scripts/extract_fit.py <활동.zip|.fit> <작업폴더>` → `training.json`, `run-data.json` 생성 + 요약 출력(세트별 페이스·목표·적중·존%·심박회복, 본훈련 존 분포, 회복 조깅).
   - 심박존 경계와 존 체류 시간은 FIT의 `time_in_zone`(mesg 216)에서 읽는다(워치 설정값). 없으면 최대심박 비율 추정 — 이때는 영상에 추정임을 밝히지 말고 사용자에게 먼저 알린다.
   - 회복 구간에 일시정지가 있는 세트는 심박 회복에서 제외하고 화면에 작게 사유를 적는다.
   - 계획 거리와 실제 거리가 다르면(예: 1km 계획, 518m 기록) 실제 값을 쓴다.
3. **음악 분석**: `python scripts/analyze_music.py <곡.mp3> <작업폴더>` → `beats.json` + 마디/에너지 표. 장면 경계를 정한다.
4. **장소·제목 확인**: 장소명은 사용자에게 묻는다. 훈련 제목은 워크아웃 이름에서 만든다(예: `2km*5+1km 롱 인터벌` → `2KM ×5 +1KM` / `롱 인터벌 빌드업`).
5. **scene.js 수정** — 아래 "교체 목록"을 모두 바꾼다.
6. **검수 스틸**: `node render.mjs --cover`, `node render.mjs --stills 2.5,8.4,…`로 장면마다 1~2장 뽑아 4×2 시트로 확인(겹침·잘림·빈 화면).
6-1. **카드**: `node render.mjs --cards` → 7장을 4×2 시트로 확인(패널에 라벨이 가리는지, 숫자 간격).
7. **전체 렌더**: `node render.mjs` (54초 기준 약 8~9분) → `./finish.sh <곡.mp3>` → `out/run-review-feed.mp4`(파일명은 자유).
8. **최종 확인**: ffprobe로 1080×1350·60fps·길이, 0~5프레임이 커버인지, 마지막이 커버인지, 음량이 원곡보다 약 2dB 낮은지(`volumedetect`).
9. 커버 PNG, MP4, 카드 PNG 7장, 캡션(`out/caption.txt`)을 사용자에게 전달(인스타 업로드 순서: 영상 → 카드 02~08).
   캡션 형식: 날짜·장소 / 훈련 유형 / 세션 요약 / 본훈련 + 세트별 페이스 + 목표 적중 / 심박존 / 회복 평균 / 다이내믹스 / 훈련 효과 / 한 줄 설명 + 유튜브 언급 / 해시태그(#우주로달리기 포함).

## scene.js 교체 목록 (기준 작업물에 하드코딩된 곳)

- 상단 데이터 블록: `RUN`, `REPS`(pace·hr·lo·hi = 목표 범위 초/km), `FINAL`, `RECS`, `ZB`(존 경계), `REPZ`/`FINALZ`/`MAINZ`(존 체류 초, [Z1..Z5]), `REPMAX`, `REPWIN`/`FINALWIN`(시계열 창, 경과초), `HRREC` — 전부 `training.json`에서 옮긴다.
- `drawCover()`: 장소, 날짜, `롱 인터벌 빌드업`, `2KM`/`×5`/`+1KM`, `세트마다 더 빠르게`, `5/5 목표 적중`, 하단 4개 지표(본훈련 거리·평균·심박·Z4 비중).
- `titleBadge()`와 `titleGroup()`(인트로 큰 제목)의 문구 — 같아야 이동 연출이 자연스럽다.
- `sIntro`: 날짜, 장소 필, `트랙 인터벌 세션`, 빌드업 문구.
- `sSummary`: 세션·본훈련 수치, 장소·기온, `2000m × 5 + 마지막 스텝`, Z4 문구. (`sMain`은 현재 미사용)
- `sReps`: 세트 수(5), `2000`/`2000m 완주`/진행 바 최대값, 칩 개수, 세트당 박 수(8), 시작 비트(16).
- `sFinal`: 목표 대비 초 차이, `마지막 518m`, 평균 심박.
- `sRecovery`, `RECAVG`: 회복 조깅 평균 거리·페이스·심박.
- `sFinal`: 오른쪽 "마지막 바퀴 약 520m" 숫자.
- `PAUSES`: 급수·휴식 구간 [시작 경과초, 길이초].
- `cards.js`의 `WORKOUT`(워크아웃 이름·스텝·목표, `training.json`의 reps/recoveries 목표값과 FIT 워크아웃 이름) 및 모든 카드의 수치·문구(장소·날짜, 표 행, 다이내믹스 값, 소개 문구·태그). 브랜드 카드 문구는 사용자 소개에 맞게 바꿀 수 있다.
- `sAnalysis`/`sChart`: 세트별 최대 심박 흐름 문구, 도넛 중앙 %, 다이내믹스 값, 훈련 효과 한 줄, 심박 회복 평균·제외 사유, N/N.
- `sOutro`: 목적·방식·결과 3줄 (세트별 단축 폭, 첫→마지막 페이스, Z4 비중 등 실제 수치로).
- `draw()`의 장면 분기 비트 인덱스, `SECS`(하단 진행 바 구간 시각), HUD 거리(13.12), `endT = b(마지막 히트)`, `DUR`(곡 길이).
- 다른 세트 거리(예: 1000m×8, 400m×12)면 `sReps`의 진행 바 눈금·문구·게이지 범위(`lo`,`hi`)와 커버 막대 스케일을 맞춘다.

## 주의

- 비트 인덱스는 0부터 센다. 엔딩은 `analyze_music.py`가 알려 준 "가장 강한 히트"에 가장 가까운 비트를 쓴다(기준 곡은 b105 = 52.88초).
- 클라우드 세션에서는 파일이 사라지므로 결과물은 저장소에 커밋하거나 사용자에게 전송한다. 음원 mp3와 원본 FIT은 저장소에 올리지 않는다.
- 렌더 시간: 1080×1350, 2샘플 모션블러 기준 1초 영상당 약 9~10초 + 후처리 약 2분.
