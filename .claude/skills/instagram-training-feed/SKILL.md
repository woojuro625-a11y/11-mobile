# 인스타그램 훈련 피드 양식

러닝 훈련 기록 한 건을 음악 비트에 맞춰 소개하는 인스타그램 피드 영상 + 커버 이미지 양식.
기준 작업물: 2026.11.04 "2km×5+1km 롱 인터벌" (목동교 멀티스포츠존), 곡 Riverside Stride(123BPM, 54초).
`template/`은 그 영상을 만든 코드 그대로이며, 새 훈련에 맞게 **데이터·문구·비트 인덱스만 바꿔서** 쓴다.

## 산출물 규격 (고정)

| 항목 | 값 |
|---|---|
| 영상 | 1080×1350 (4:5 피드), **60fps**, H.264 + AAC, 길이 = 곡 길이 |
| 커버 | `out/cover.png` 1080×1350. **영상의 첫 0.1초(6프레임) = 커버 그대로** |
| 엔딩 | 곡의 마지막 강한 히트에 맞춰 커버로 복귀 → 피드 반복 재생 시 루프가 이어짐 |
| 음악 볼륨 | 원곡의 **80%** (`finish.sh`의 `volume=0.8`), 끝 0.25초 페이드 |
| 모션블러 | 프레임당 2샘플(180° 셔터), 후처리로 약한 블룸 + 그레인 |

## 표기 · 문구 규칙 (사용자 확정 사항)

- **페이스는 `3'54"` 형식** (분'초"). `/km` 단위 붙이지 않음. `fmtPace()` 사용.
- **제목은 `2KM`**(Anton 대문자), **설명 문구는 m 단위**: "2000m × 5 + 마지막 스텝", "2000m 동안의 심박 변화".
- **훈련 시작 시각은 넣지 않는다.** 날짜·요일만.
- **장소를 표기**한다 (핀 아이콘 + 장소명). 장소는 사용자에게 받는다 — GPS로 추정해 지명을 쓰지 말 것.
- **평균 러닝 파워는 넣지 않는다.**
- 사용자 실명, 절대 GPS 좌표는 넣지 않는다 (FIT 프로필에 이름이 있어도). `run-data.json`의 route는 상대 미터 좌표만.
- 모든 화면 문구는 한국어. 숫자·단위(km, m, bpm, spm, ms, kcal, Z1~Z5)만 예외.
- 마지막 장면은 감성 문구가 아니라 **"이 훈련은" 요약**: 01 목적 / 02 방식 / 03 결과.

## 디자인 시스템

- 색: 배경 `#0B0D10`, 포인트 라임 `#D4FF3A`, 흰색 `#F3F2EC`, 심박 코랄 `#FF5A5F`, 회복 스카이 `#5CC8FF`, 회복 장면 배경 `#081521`.
- 심박존 색(가민 관례): Z1 `#7C8A9C` 회색 · Z2 `#5CC8FF` 파랑 · Z3 `#3DDC84` 초록 · Z4 `#FFB020` 주황 · Z5 `#FF5A5F` 빨강.
- 폰트: 한글 **Pretendard**(700~900), 큰 숫자·제목 **Anton**, 작은 라벨 **JetBrains Mono**.
- 모티프: 원근감 있는 트랙 오벌 + 라임 러너 점과 잔상, 속도선, 마스크 슬라이드 업 텍스트, 슬롯머신 숫자 롤, 비트마다 미세 줌 펀치(±1.2%)와 글로우 펄스.
- 상단 고정 HUD: 왼쪽 **훈련 이름 배지**(`2KM ×5 +1KM 롱 인터벌`), 오른쪽 진행 거리. 하단: 장면 구간 진행 바 + 현재 장면 이름.
- 여백 72px, 장면 왼쪽 위 `— 0N 섹션명` 라벨.

## 장면 구성 (곡 구조에 맞춘 비트 동기화)

비트 인덱스 `b(i)` = `beats.json`의 i번째 비트 시각. 아래는 기준 곡의 배치이며, 새 곡은 `analyze_music.py`가 출력한 마디/에너지 표를 보고 같은 **역할**을 같은 **음악 구간**에 배치한다.

| 기준 비트 | 장면 | 내용 · 규칙 |
|---|---|---|
| t < 0.1s | 커버 | `drawCover()` 정지 화면 |
| 0.1s ~ b12 (인트로, 3마디) | 인트로 | 날짜 타이핑 → b0 "오늘의 / 훈련" + 장소 핀 필 → b4~b7 `2KM` `×5` `+1KM` `롱 인터벌` 비트마다 슬램 → b8 **제목이 작아지며 왼쪽 위 배지 자리로 이동, 이후 엔딩까지 유지** → "빌드업 / 세트마다 페이스를 끌어올린다" |
| b12 ~ b16 (1마디) | 세션 요약 카드 | **카드 한 장에 전부**: 장소·날짜·기온 / 총거리·운동시간·평균페이스·평균심박·최대심박·칼로리. 덜 중요하므로 짧게 |
| b16 ~ b20 (1마디) | 본훈련 개요 | 본훈련 거리·시간·평균페이스·평균심박 + **본훈련 심박존 분포 막대** + "Z4 역치 구간에서 mm:ss (n%)" |
| b20 ~ b28 (2마디) | 세션 전체 심박 그래프 | 존 색 밴드 위 존 색상 심박 라인, 세트 구간 음영이 비트마다 하나씩, 세트별 최대 심박 흐름 문구 |
| b28 ~ (드롭) | **본훈련 세트 × N** | 드롭에서 라임 플래시. **세트당 최소 6박**. 세트 번호 + 우측 큰 **`2000m`** / 페이스 슬롯 롤 / **0→2000m 거리 진행 바(500m 눈금) → "2000m 완주"** / 목표 범위 게이지 + 적중 체크 / 평균·최대 심박 / 세트 심박존 막대 / "2000m 동안의 심박 변화" 그래프 / 하단 세트 페이스 칩 |
| 다음 6박 | 라스트 스퍼트 | 마지막 스텝 페이스 큰 숫자 + 잔상, 목표 대비 몇 초 빠른지, 거리·평균 심박 필 → 브레이크 직전 줌 인 |
| 브레이크 (2마디) | 회복 조깅 | 파란 톤, 호흡 원, 회복 구간 페이스 칩, 평균 페이스·심박 |
| 재상승 (6마디, 마디당 1장) | 분석 | ① 본훈련 심박존 도넛 + 존별 시간 ② 세트별 존 100% 누적 막대(Z4+Z5 %) ③ 러닝 다이내믹스(케이던스·보폭·지면접촉) ④ 세트 후 1분 심박 회복 ⑤ **N/N 목표 페이스 적중** ⑥ 훈련 효과(유산소/무산소) |
| 드롭아웃 ~ 마지막 히트 | "이 훈련은" 요약 | 01 목적 · 02 방식 · 03 결과, 2박 간격으로 등장 |
| 마지막 히트 ~ 끝 | 엔드 카드 | 라임 플래시 후 커버로 복귀(`endT = b(마지막 히트 비트)`) |

곡이 다르면: 드롭(▲ 상승)에 세트 시작을, 브레이크(▼ 하강)에 회복 조깅을, 마지막 큰 에너지 구간에 분석을 둔다. 세트 수 N × 6박이 들어가지 않으면 요약/개요/그래프를 줄이고 세트 화면 길이는 지킨다(사용자 피드백: 세트 화면이 짧으면 안 됨).

## 작업 순서

1. **환경 준비**
   ```bash
   python3 -m venv <scratch>/venv && <scratch>/venv/bin/pip install fitparse numpy librosa soundfile
   ```
   새 작업 폴더를 만들고 `template/`의 파일을 복사한 뒤 `npm i` (pretendard, @fontsource/anton). Chromium/Playwright는 환경에 설치된 것을 쓴다.
2. **데이터 추출**: `python scripts/extract_fit.py <활동.zip|.fit> <작업폴더>` → `training.json`, `run-data.json` 생성 + 요약 출력(세트별 페이스·목표·적중·존%·심박회복, 본훈련 존 분포, 회복 조깅).
   - 심박존 경계와 존 체류 시간은 FIT의 `time_in_zone`(mesg 216)에서 읽는다(워치 설정값). 없으면 최대심박 비율 추정 — 이때는 영상에 추정임을 밝히지 말고 사용자에게 먼저 알린다.
   - 회복 구간에 일시정지가 있는 세트는 심박 회복에서 제외하고 화면에 작게 사유를 적는다.
   - 계획 거리와 실제 거리가 다르면(예: 1km 계획, 518m 기록) 실제 값을 쓴다.
3. **음악 분석**: `python scripts/analyze_music.py <곡.mp3> <작업폴더>` → `beats.json` + 마디/에너지 표. 장면 경계를 정한다.
4. **장소·제목 확인**: 장소명은 사용자에게 묻는다. 훈련 제목은 워크아웃 이름에서 만든다(예: `2km*5+1km 롱 인터벌` → `2KM ×5 +1KM` / `롱 인터벌 빌드업`).
5. **scene.js 수정** — 아래 "교체 목록"을 모두 바꾼다.
6. **검수 스틸**: `node render.mjs --cover`, `node render.mjs --stills 2.5,8.4,…`로 장면마다 1~2장 뽑아 4×2 시트로 확인(겹침·잘림·빈 화면).
7. **전체 렌더**: `node render.mjs` (54초 기준 약 8~9분) → `./finish.sh <곡.mp3>` → `out/run-review-feed.mp4`(파일명은 자유).
8. **최종 확인**: ffprobe로 1080×1350·60fps·길이, 0~5프레임이 커버인지, 마지막이 커버인지, 음량이 원곡보다 약 2dB 낮은지(`volumedetect`).
9. 커버 PNG와 MP4를 사용자에게 전달.

## scene.js 교체 목록 (기준 작업물에 하드코딩된 곳)

- 상단 데이터 블록: `RUN`, `REPS`(pace·hr·lo·hi = 목표 범위 초/km), `FINAL`, `RECS`, `ZB`(존 경계), `REPZ`/`FINALZ`/`MAINZ`(존 체류 초, [Z1..Z5]), `REPMAX`, `REPWIN`/`FINALWIN`(시계열 창, 경과초), `HRREC` — 전부 `training.json`에서 옮긴다.
- `drawCover()`: 장소, 날짜, `롱 인터벌 빌드업`, `2KM`/`×5`/`+1KM`, `세트마다 더 빠르게`, `5/5 목표 적중`, 하단 4개 지표(본훈련 거리·평균·심박·Z4 비중).
- `titleBadge()`와 인트로의 제목 텍스트(둘이 같은 문구여야 이동 연출이 자연스럽다).
- `sIntro`: 날짜, 장소 필, `트랙 인터벌 세션`, 빌드업 문구.
- `sSummary`, `sMain`: 수치·장소·기온, `2000m × 5 + 마지막 스텝`, Z4 문구.
- `sChart`: 세트별 최대 심박 흐름 문구, 회복 문구.
- `sReps`: 세트 수(5), `2000`/`2000m 완주`/진행 바 최대값, 칩 개수, 세트당 박 수(6).
- `sFinal`: 목표 대비 초 차이, `마지막 518m`, 평균 심박.
- `sRecovery`: 평균 페이스·심박.
- `sAnalysis`: 도넛 중앙 %, 다이내믹스 값, 심박 회복 평균·제외 사유, N/N, 훈련 효과 값과 문구.
- `sOutro`: 목적·방식·결과 3줄 (세트별 단축 폭, 첫→마지막 페이스, Z4 비중 등 실제 수치로).
- `draw()`의 장면 분기 비트 인덱스, `SECS`(하단 진행 바 구간 시각), HUD 거리(13.12), `endT = b(마지막 히트)`, `DUR`(곡 길이).
- 다른 세트 거리(예: 1000m×8, 400m×12)면 `sReps`의 진행 바 눈금·문구·게이지 범위(`lo`,`hi`)와 커버 막대 스케일을 맞춘다.

## 주의

- 비트 인덱스는 0부터 센다. 엔딩은 `analyze_music.py`가 알려 준 "가장 강한 히트"에 가장 가까운 비트를 쓴다(기준 곡은 b105 = 52.88초).
- 클라우드 세션에서는 파일이 사라지므로 결과물은 저장소에 커밋하거나 사용자에게 전송한다. 음원 mp3와 원본 FIT은 저장소에 올리지 않는다.
- 렌더 시간: 1080×1350, 2샘플 모션블러 기준 1초 영상당 약 9~10초 + 후처리 약 2분.
