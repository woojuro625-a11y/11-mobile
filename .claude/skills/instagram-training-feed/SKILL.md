# 인스타그램 훈련 피드 양식

러닝 훈련 한 건을 인스타그램 캐러셀 게시물 한 세트로 만든다: **1번 슬라이드 = 음악 비트에 맞춘 리뷰 영상, 2~8번 = 지표 카드**, 그리고 캡션.
기준 작업물: 2026.11.04 "2km*5+1km 롱 인터벌" · 목동교 멀티스포츠존 · 곡 Riverside Stride(약 123BPM, 54초) · 계정 @woojuro_running(채널명 "우주로 달리기").
`template/`은 기준 작업물을 만든 코드 그대로다. 새 훈련은 **데이터 · 문구 · 비트 인덱스만 바꿔서** 쓴다.

## 산출물

| 파일 | 규격 |
|---|---|
| `out/run-review-feed.mp4` | 1080×1350(4:5), **60fps**, H.264 + AAC, 길이 = 곡 길이. **첫 0.1초(6프레임) = 커버**, 곡의 마지막 강한 히트에 커버로 복귀(반복 재생 시 루프) |
| `out/cover.png` | 1080×1350 커버(영상 첫 프레임과 동일) |
| `out/cards/card-02~08-*.png` | 1080×1350 카드 7장 (영상 다음 2~8번 슬라이드) |
| `out/workout-plan.png` | 1080×374 가민 워크아웃 구성 이미지(3번 카드 상단과 동일) |
| `out/caption.txt` | 인스타 캡션 |

오디오: 원곡의 **80%** 볼륨(`finish.sh`의 `volume=0.8`), 끝 0.25초 페이드. 영상 후처리: 프레임당 2샘플 모션블러, 약한 블룸·그레인.

## 사용자 확정 규칙 (반드시 지킨다)

**표기**
- 페이스는 **`3'54"`** 형식(분'초"). `/km`를 붙이지 않는다. `fmtPace()`.
- 목표 페이스는 **범위**다. 하한·상한을 같은 밝기로 `4'00"~4'10"`처럼 한 줄에 묶는다(하한만 강조하면 그 값이 목표처럼 보인다). 범위 구분 기호는 카드에서 `~`.
- 제목은 `2KM`(Anton 대문자), **설명 문구는 m 단위**("2000m × 5 + 마지막 스텝", "2000m 동안의 심박 변화").
- **영상·카드 문구에는 쉼표(,)와 마침표(.)를 쓰지 않는다.** 구분이 필요하면 ` · `. 숫자의 소수점은 예외. (캡션은 아래 '캡션 패턴'의 사용자 문체를 따른다 — 문장 끝 마침표 허용)
- 모든 문구는 한국어. 숫자·단위(km, m, bpm, spm, ms, kcal, Z1~Z5)와 계정 아이디만 예외.

**넣지 않는 것**
- 훈련 **시작 시각**(날짜·요일만), 사용자 **실명**, **절대 GPS 좌표**(route는 상대 미터 좌표만).
- **평균 러닝 파워**, **세트 후 심박 회복** 장면/수치.
- 큰 숫자 잔상·배경 글로우의 진한 라임(눈이 아프다는 피드백) → 잔상은 회색 `#6B7480` 저투명도.
- 로고에 금색·노랑 그라데이션·그림자·기울임.

**넣는 것**
- **장소**(핀 아이콘 + 장소명). 장소명은 사용자에게 받는다 — GPS로 지명을 추정하지 않는다.
- 회복 구간은 **평균값**: 평균 거리(m) · 평균 페이스 · 평균 심박.
- **심박 그래프가 끊긴 곳 = 급수·완전 휴식**(시계 일시정지): 물방울 마커 + 길이(초) + 범례.
- 훈련 유형(예: "빌드업 롱 인터벌")을 영상 마지막 요약에서 크게 강조.

- 심박존 색: Z1 `#7C8A9C` · Z2 `#5CC8FF` · Z3 `#3DDC84` · Z4 `#FFB020` · Z5 `#FF5A5F`. 존 이름: 워밍업 · 쉬움 · 유산소 · 역치 · 최대.
- 서체: 한글 Pretendard(700~900) · 숫자/제목 Anton · 작은 라벨 JetBrains Mono · **"우주로 달리기" 로고 Hahmlet ExtraBold, 흰색 한 색**(`window.BRAND_SIMPLE_FONT`, 사용자 선택. 후보 비교는 `template/font-options.html`).
- 영상 모티프: 트랙 오벌 + 라임 러너, 속도선, 마스크 슬라이드 업, 슬롯 숫자 롤, 비트마다 미세 줌 펀치. 상단 고정 **훈련 이름 배지**(`2KM ×5 +1KM 롱 인터벌`) + 진행 거리, 하단 구간 진행 바.
- 여백 72px.

## 영상 장면 구성 (비트 동기화)

`b(i)` = `beats.json`의 i번째 비트 시각(0부터). 아래는 기준 곡 배치이며, 새 곡은 `analyze_music.py`의 마디·에너지 표를 보고 **같은 역할을 같은 음악 구간에** 둔다.

| 기준 비트 | 장면 | 내용 |
|---|---|---|
| t < 0.1s | 커버 | `drawCover()` |
| 0.1s ~ b8 | 훈련 소개(길게) | 날짜 타이핑 + 장소 → "오늘의 훈련" → `2KM` `×5` `+1KM` `롱 인터벌 빌드업` 비트마다 슬램 → "2000m × 5 · 세트마다 페이스를 끌어올린다" → 제목 유지 |
| b8 ~ b16 | 요약 카드 한 장(짧게) | 제목이 상단 배지로 이동(엔딩까지 유지). 세션 전체(작게) / **본훈련**(4개 한 줄) + 본훈련 심박존 막대 / **회복구간**(파란색: 랩 버튼까지 조깅·목표 범위, 평균 거리·평균 페이스·평균 심박·급수·휴식 횟수) |
| b16 ~ b56 | **본훈련 세트(최대한 길게, 세트당 8박)** | 첫 에너지 상승에 라임 플래시. 세트 번호 + 큰 `2000m` · 페이스 롤 · 0→2000m 진행 바 → "2000m 완주" · 목표 범위 게이지 + 적중 · 평균/최대 심박 · 세트 존 막대 · "2000m 동안의 심박 변화" · 세트 칩 |
| b56 ~ b64 | 라스트 스퍼트 | "라스트 스퍼트" 옆 빈 공간에 **"마지막 바퀴 약 520m"** 크게 · 페이스 큰 숫자(회색 잔상) · 목표 대비 · 목표 범위·평균 심박 |
| b64 ~ b72 (브레이크) | **회복구간** | 제목 "회복구간" 한 단어 + 옆에 목표 유지 체크 · 총 거리 · 총 시간 · 급수·휴식 횟수/시간. N회 평균(거리·페이스·심박)과 구간별 칩을 **한 번에 표시**하고 비트마다 칩 하이라이트로 대기 |
| b72 ~ b96 | 분석 | ① 세션 심박 그래프(급수·휴식 마커) ② 본훈련 심박존 도넛 ③ 세트별 존 누적 막대 **2마디**(두 번째 마디에 세트를 하나씩 짚음) ④ N/N 목표 적중 ⑤ 러닝 다이내믹스 + 훈련 효과 한 줄 |
| b96 ~ 마지막 히트 | "이 훈련은" | **훈련 유형 라임 박스 강조** + 한 줄 설명 → 01 목적 · 02 방식 · 03 결과 |
| 마지막 히트(b105) ~ 끝 | 엔드 | 라임 플래시 후 커버 |

우선순위(사용자 피드백): **세트 화면 길이 > 시작부 훈련 이름 노출 > 요약 짧게**. 시간이 모자라면 요약·분석을 줄인다.

**구성이 다른 훈련** (두 번째 작업물 `run-review-1013`: 3k*3 + 2k, 2026.10.13)
- 반복 세트 N개는 세트 화면(b16부터, 세트당 박 수 = 가용 박 ÷ N, 마디 단위 권장 — 3세트면 12박씩 b16~b52), **마지막의 다른 거리 세트는 "라스트" 장면**(b52~b64: 큰 거리 숫자 + 페이스 + 목표 범위 + 그 세트의 심박 변화 그래프)으로 보여준다.
- `SETD`(반복 거리)·`SETN`(반복 수)로 진행 바 눈금(500m 단위, 1000m마다 라벨)·문구·칩 수가 바뀐다.
- **목표 미달 세트는 그대로 보여준다**: `hitOf(r) = pace ≤ hi + 0.5`. 미달이면 세트 화면 "목표보다 N초 느림"(주황), 결과 화면·표는 주황 원 "+N초", 결과 숫자는 `적중/전체`(예 3/4) + 짧은 설명. 적중을 꾸며내지 않는다.
- 회복 목표가 없으면(워크아웃 회복 스텝 `target_type: open`) "랩 버튼까지 자유 조깅"으로 쓰고 목표 범위를 넣지 않는다.
- 날짜·요일은 현지 시각 기준(`extract_fit.py`가 처리). 훈련 종료 후 눌린 100m 미만 랩은 회복에서 제외(자동).

## 피드 카드 (cards.js)

공통: 상단 훈련 이름 배지 + `n / 8`, 큰 제목 + 부제, 하단 장소·날짜 + 흰색 한 줄 로고 "우주로 달리기".

| 카드 | 내용 |
|---|---|
| 02 세션 요약 | 줄 구성 **거리·시간 / 평균 페이스·칼로리 / 평균 심박·최대 심박**(심박 둘은 같은 줄) + **본훈련 패널**(거리·시간·평균 페이스·평균 심박) + **회복구간 패널**(파란 톤: "랩 버튼까지 조깅 · 목표 5'00"~6'30"" / 평균 거리·평균 페이스·평균 심박·급수·휴식 횟수) |
| 03 세트별 기록 | 상단 **가민 워크아웃 구성**: 워크아웃 이름(FIT 원문), 질주·회복 블록(길이 비례), 블록 아래 목표 범위 + 괄호선, 블록 사이 점선 화살표 **"-5초"** 배지, 우상단 "목표 범위 세트마다 -5초". 하단 표: 세트 · 거리 · 페이스 · 목표 범위 ✓ · 심박 평균/최대 · Z4+Z5 % |
| 04 심박 변화 | 세션 심박 그래프(존 밴드, 존 라벨은 그래프 밖 왼쪽) + 세트 음영 + 급수·휴식 마커/범례 + 세트별 최대 심박 칩 |
| 05 심박존 분석 | 본훈련 존 도넛 + 존별 시간·% + 세트별 존 누적 막대 |
| 06 회복 & 라스트 | 회복 조깅 N회 평균 + 구간 칩 / 라스트 페이스 + 약 520m + 목표 대비 |
| 07 러닝 다이내믹스 | 케이던스·보폭·지면 접촉·수직 진폭·수직 비율·최고 속도 + 훈련 효과 게이지 |
| 08 우주로 달리기 | 별 배경, 정가운데 흰색 로고(Hahmlet), 유튜브 아이콘 + "유튜브 채널", 인스타 프로필 줄(그라데이션 링 + **프로필 사진 원형 크롭** + `woojuro_running` + "우주로 달리기" + 파란 `#0095F6` 팔로우 + 탭 표시). 다른 문구 없음 |

프로필 사진: `assets/profile.jpg`(저장소에 커밋하지 않음). 크롭은 **실제 인스타 프로필과 같은 구도**(얼굴이 원 지름의 약 1/3, 위로 하늘·아래로 상체) — 기준 사진은 `CS=1320, CX=220, CY=82`. 사진이 바뀌면 사용자 프로필 스크린샷과 나란히 비교해 맞춘다.

## 작업 순서

1. **환경**: `python3 -m venv <scratch>/venv && <scratch>/venv/bin/pip install fitparse numpy librosa soundfile` · 새 작업 폴더에 `template/` 복사 → `npm i`. Chromium/Playwright는 환경에 설치된 것을 쓴다.
2. **데이터**: `python -I scripts/extract_fit.py <활동.zip|.fit> <작업폴더>` → `training.json` · `run-data.json` + 요약(세트별 페이스·목표·적중·존%, 본훈련 존, 회복 평균 거리·페이스·심박, 급수·휴식 `pauses`, 워크아웃 이름).
   - 심박존 경계·체류 시간은 FIT `time_in_zone`(mesg 216, 워치 설정값). 없으면 최대심박 비율로 추정하되 사용자에게 먼저 알린다.
   - 계획과 실제 거리가 다르면(1km 계획 → 518m) 실제 값.
3. **음악**: `python -I scripts/analyze_music.py <곡.mp3> <작업폴더>` → `beats.json` + 마디/에너지 표 + 마지막 히트 비트.
4. **사용자 확인**: 장소명, (바뀌었으면) 프로필 사진.
5. **코드 수정**: 아래 교체 목록.
6. **검수**: `node render.mjs --cover` · `--stills t1,t2,…`(장면마다) · `--cards` → 카드는 한 장씩 원본 크기로 보고 겹침·잘림·구분 기호·쉼표/마침표를 확인.
7. **렌더**: `node render.mjs`(54초 기준 약 9분) → `./finish.sh <곡.mp3>`.
8. **확인**: ffprobe 1080×1350·60fps·길이 / 0~5프레임 = 커버 / 마지막 = 커버 / 음량 원곡 대비 약 -2dB.
9. **전달**: 영상, 커버, 카드 7장, 워크아웃 이미지, 캡션(캡션 패턴으로 초안 → ♤ 소감은 사용자 확인). 업로드는 **캐러셀 한 게시물**(영상 → 카드 02~08). 영상만 단독 업로드하면 릴스가 되어 비팔로워에게 더 퍼지므로, 사용자가 원하지 않으면 캐러셀로 올린다. 캐러셀에 영상이 있으면 인스타 음악을 카드에만 따로 넣을 수 없다.

캡션은 아래 **캡션 패턴**을 따른다(사용자가 직접 다듬은 최종본 = `template/caption-example.txt`).

## 캡션 패턴 (사용자 최종본에서 학습)

구조와 문체를 그대로 따른다. 수치만 새 훈련 값으로 바꾸고, ♤ 개인 소감은 사용자 말투를 흉내 내되 **내용은 사용자에게 확인**받는다(지어내지 않는다).

```
[스피드 훈련 일지]                           ← 맨 위 대괄호 분류 머리말 (훈련 종류에 맞게: 스피드/지구력/회복 등)

🏃 {훈련 유형} | {질주거리}m × {N} + {마지막 실제거리 반올림}m x 1   ← 구성은 m 단위, 마지막 스텝은 실제로 뛴 거리(약 500m)
📍 {장소} · {YYYY.MM.DD}

{훈련 소개 1문장 — 무엇을 어떻게 반복했는지, "~훈련이었습니다."}

{마지막 세트/스텝 이야기 — 짧게 두 줄로 끊어 씀}

{회복 방식 — 회복 거리·급수·여유롭게 회복}


🎯 훈련 목적
{생리적 목적} · {레이스 목표와 연결 (예: 10km 레이스 페이스)}

🔥 핵심 기록
{질주거리}m
{세트별 페이스 → 화살표로 나열}

{마지막 스텝 설명 (예: 마지막 거리를 줄여서 약 500m)}
{마지막 페이스}

본훈련 {거리}km · 평균 {페이스} · 심박 Z4(역치) {%}


♤
{개인 훈련 철학 · 회복/급수 습관 · 본 훈련 스피드는 타협하지 않는다는 태도}
{다음 훈련에 대한 기대 + 이모지 하나 (😂)}


#러닝 #인터벌 #훈련일지 #훈지 #달리기   ← 해시태그는 정확히 5개 (인스타 제한)
```

문체 규칙
- 존댓말 1인칭 서술(**~습니다 / ~했습니다 / ~하네요**). 마침표·쉼표는 사용자 문장 그대로 허용.
- 짧은 문단 + 빈 줄로 호흡을 끊는다. 섹션 사이는 빈 줄 두 개.
- 넣지 않는 것: 유튜브 홍보 문구, "다음 카드에서" 안내, 세부 지표 나열(카드에 맡김), 해시태그 6개 이상.
- 마지막 스텝은 계획 거리(1km)가 아니라 **실제로 뛴 바퀴 기준**으로 쓴다(목동교 트랙 1바퀴 ≈ 500m → 518m는 "약 500m").
- 회복은 "약 {평균 회복 거리}m" + 급수 언급.

## 교체 목록 (기준 작업물에 하드코딩된 값)

- `scene.js` 데이터 블록: `RUN` `REPS`(pace·hr·lo·hi) `FINAL` `RECS` `RECAVG` `ZB` `REPZ` `FINALZ` `MAINZ` `REPMAX` `REPWIN` `FINALWIN` `PAUSES` ← `training.json`.
- 문구: `drawCover`(장소·날짜·제목·막대·하단 지표) · `titleGroup`/`titleBadge`(같은 문구) · `sIntro`(날짜·장소) · `sSummary` · `sReps`(세트 수 5, 2000m, 세트당 8박, 시작 b16) · `sFinal`(약 520m, 목표 차이, 심박) · `sRecovery`(총 거리 2.60km · 총 시간 16:08 · 회복 목표) · `sChart`(세트별 최대 심박 흐름) · `sAnalysis`(도넛 %, 다이내믹스, 훈련 효과) · `sOutro`(훈련 유형, 목적·방식·결과).
- 타이밍: `draw()` 분기 비트, `SECS`, HUD 총거리, `endT = b(마지막 히트)`, `DUR`.
- `cards.js`: `WORKOUT`(이름·스텝·목표·회복 목표), 카드별 수치·표 행·다이내믹스 값, `TOTAL_SLIDES`, 프로필 크롭.
- 세트 거리가 다르면(1000m×8, 400m×12 등) 진행 바 눈금·게이지 범위·커버 막대 스케일·"-N초" 배지를 맞춘다.

## 장소 메모

- **목동교 멀티스포츠존 트랙 한 바퀴 ≈ 500m**(사용자 설명, 팔로워들도 알고 있음). 캡션에서는 마지막 한 바퀴 스텝을 "약 500m"로 쓴다. 카드·영상의 측정값 표기(약 520m / 518m)는 그대로 둔다.

## 주의

- 비트 인덱스는 0부터. 엔딩은 `analyze_music.py`가 알려준 가장 강한 히트에 가장 가까운 비트.
- 음원 mp3, 원본 FIT, 프로필 사진 원본은 저장소에 올리지 않는다.
- 클라우드 세션 파일은 사라지므로 결과물은 커밋하거나 사용자에게 전송한다.
- `render.mjs` 옵션: `--cover` · `--stills` · `--cards`(+ workout-plan.png) · `--brand-variants`(로고 시안 비교).
