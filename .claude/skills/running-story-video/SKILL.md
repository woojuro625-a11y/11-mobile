# 러닝 스토리 영상 만들기

저장소 `running-story/`에 5개 양식이 완결된 폴더로 저장되어 있다. **먼저 `running-story/README.md`와 만들 양식 폴더의 `README.md`를 읽는다.** 그 문서들이 구성, 규칙, 만드는 순서의 기준이다.

## 받는 것
- 가민 FIT 파일(zip 가능), 가민 커넥트 기록 캡처, (있으면) 그날 사진들
- 채팅으로 제목·짧은 메모·후기(가민 메모, 줄바꿈 그대로). FIT에는 제목·메모가 없다
- 어떤 양식으로 만들지 (말이 없으면 물어보거나 다섯 개 모두 만들지 확인)
- 노래를 쓰는 양식에 새 노래를 주면: 노래를 분석해서(템포·마디·드롭·소리 성격·조성) 편집 방식과 컨셉을 노래에 맞게 정한다. 제목보다 소리를 기준으로

## 순서 (자세한 명령은 README)
1. 양식 폴더를 작업 폴더로 복사해서 작업 (저장된 양식은 예시 영상과 함께 그대로 둔다)
2. `prep_run.py` → `breaks.py`로 `data.js`
3. 캡처: 1안은 원본, 2~5안은 `cut_memo.py`로 메모 본문을 잘라 붙이고 `CAP.h` 조정
4. 사진을 양식에 맞게 넣고 `RUN`(제목·메모·후기·사진)만 고친다. 나머지는 데이터에서 자동
5. 엔딩 메모 강조는 스킬 `running-memo-emphasis`
6. 글꼴 부분집합 → 렌더(60fps) → 효과음(+노래) 섞기 → 합치기
7. **QC**: `running-story/qc.sh`로 0.2초마다 큰 시트 + 글자 영역 원본 크기 확인. 글자가 가려지거나 겹치거나 잘린 곳, 줄바꿈·숫자가 원문과 다른 곳, 쉼표·마침표가 생긴 곳이 없어야 한다. 문제가 있으면 고치고 다시 렌더
8. 결과를 `Downloads/`에 저장하고 파일 카드로 보내고, 한국어로 무엇을 했는지 짧게 설명. 커밋·푸시

## 놓치기 쉬운 규칙
- 문장에 쉼표·마침표 없음, 한글 라벨, 심박수 숫자는 그 존 색
- 스플릿은 1km부터 위에서 아래로, 스퍼트는 따로 비추고 카드를 남긴다
- 가민 캡처는 확대·덧그림 금지, 전체가 잘리지 않게
- 메모는 사용자의 줄바꿈 그대로
- 스타 러너는 진행 방향을 본다. 가려질 자리에 글자를 쓰지 않는다
- 양식의 분위기를 지킨다: 5안은 박자 펌핑 없이 차분하게, 4안은 실제 드럼 타격에 맞춰 격하게, 3안 심박존 EQ 펌핑은 3안에서만
